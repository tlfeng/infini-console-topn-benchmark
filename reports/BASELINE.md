# TopN 基线（长期对照锚点）

本文件是 TopN 准确度与性能的**基线汇总**。每次升级 Console / Easysearch、调整配置或优化算法后，
按下方「复跑与对照」评测一轮，把结果与本文件的数字对比，并在文末「轮次记录」表追加一行，
即可量化每次变化的收益。

## 环境版本

| 项 | 基线值 |
|---|---|
| Easysearch | `easysearch-3.0.0-3073`（性能基准另测于 2.1.2，见 perf 报告） |
| Console | `console-1.30.3-2407` |
| 硬件（准确度轮） | 16 核 / 15GB WSL2，10 实例，见根 README §6 内存调优 |
| 硬件（性能基准） | Apple M4，单节点隔离实例，JVM 堆 1 GiB |
| 基线日期 | 2026-11-20（准确度）/ 2026-11-19（性能） |

## 准确度基线

判据：`miss`（真 TopN 中未上榜成员数）、`miss_leader`（榜首是否一致），见根 README §1。
**长期目标：Top5 命中率 100%（所有图 `miss=0`）、榜首一致率 100%。**

| 场景 | 有数据的图 | Top5 完全一致 | 榜首一致 | 报告 |
|---|---|---|---|---|
| 索引页签（单节点 9201） | 23 | **1/23** | **13/23** | [topn_report_example.md](topn_report_example.md) |
| 节点页签（8 节点，可写） | 11 | **2/11** | **6/11** | [node_topn_example.md](node_topn_example.md) |
| 节点页签（8 节点，按需只读） | 11 | **2/11** | **8/11** | [node_topn_freeze_example.md](node_topn_freeze_example.md) |

补充观察：

- 索引页签 23 张图的榜单成员全部相同（同一组 5 个索引），与各指标真值榜首错位严重
- 节点页签 11 张图的榜单成员同样完全相同（同一组 5 个节点），而真值榜首分布差异很大
- 「低流量但单指标突出」的画像实体（bulk_store / slow_query / scroll_ctx 等）是未上榜的重灾区，
  也是未来改进最敏感的样本

## 性能基线（查询层，隔离实例）

完整数据见 [perf_topn_benchmark.md](perf_topn_benchmark.md)（三种选榜算法对比，p50/p95）。

| 组合 | 候选并集路径 `old_*` | 直查快路径 `new_store` | 复合分页路径 `new_rate` |
|---|---:|---:|---:|
| 存储 Top5 · 100 实体 / 24h | 63.2 ms | **2.8 ms** | — |
| 存储 Top5 · 5,000 实体 / 24h | 95.9 ms | **73.9 ms** | — |
| 速率 Top5 · 1,000 实体 / 15min | 2.8 ms | — | 104.3 ms |
| 速率 Top5 · 5,000 实体 / 24h | 95.8 ms | — | 3,147.0 ms |

要点：直查快路径在所有规模下更快或持平且榜单与真值一致（长窗口收益最大，约 22 倍）；
精确速率需复合分页路径，大实体数 / 长窗口下有数量级成本，是后续优化的重点方向。

## 复跑与对照

```bash
# 1) 环境按根 README §3 启动，节点页签或索引页签跑一轮
bash repro/41_run_node.sh --duration 200        # 或 40_run_all.sh
python3 repro/42_score.py                       # 本轮评分卡（命中率 / 榜首一致率）

# 2) 性能维度（独立，不需要 Console）
python3 repro/benchmark_topn.py --counts 100 --windows 86400

# 3) 与本文件对照，差异记入下方「轮次记录」
```
