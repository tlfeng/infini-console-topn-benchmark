# TopN 查询层性能基准：三种选榜算法对比

脚本：`repro/benchmark_topn.py`，原始数据：`perf_topn_benchmark.json`（每行一个组合）。

## 方法

- **环境**：Apple M4，单节点 Easysearch 2.1.2（build `e1cb61d8…`），JVM 堆 1 GiB，监控索引 3 主分片、无副本、关闭查询请求缓存。
- **造数**：稠密、不可变合成样本。15 分钟窗口每 20 秒采样、24 小时窗口每 60 秒采样；存储峰值在高位实体（`idx-…` 尾号大）、写入速率峰值在低位实体（尾号小），两类榜首不同。
- **对照算法**：`old_*` = 候选并集路径（读写活动候选：固定 60s 桶差分峰值、`terms` partition 0；候选桶超限则无名称过滤按存储出图）+ 按存储排序展示；`new_store` = 直查快路径（`max` DESC 两阶段）；`new_rate` = 复合分页路径（`composite` 分页，页 128 + 客户端差分算分）。`old_*` / `new_*` 为历史输出键名，与留档结果兼容。
- **测量**：每组合预热 5 次、单并发交错执行 20 次；p50/p95 为客户端墙钟（含本地 HTTP、JSON 解析与客户端选榜），非生产 Console API 或浏览器延迟。固定数据无需 PIT；不含并发、授权、采集写入。
- **正确性**：直查快路径榜单与造数基准逐名断言一致；候选并集路径只记录命中数（`matches`）与降级次数（`fallbacks`）。

## 结论

- **直查快路径：所有规模下更快或持平，且榜单与真值一致。** 收益最大在长窗口：100 实体 / 24 小时较候选并集路径快约 22 倍（后者要拉全部分区 0 的时间桶）。
- **精确速率（复合分页）：新增成本。** 1,000 实体 / 15 分钟 p50 约为候选并集路径 37 倍（后者未命中全部正确 Top5），搜索 2 → 9 次、响应 55 KB → 4.87 MB；5,000 实体 / 24 小时 p50 约 3.1 秒、41 次搜索、78 MB。Top5 与 Top20 的复合分页数据量几乎相同。
- **候选并集路径响应并不小：** 24 小时窗口下自带约 2.2–2.3 MB（Top20 约 7.8–8.8 MB）时间桶数据，且 100 / 5,000 实体未超限时榜单命中率仍为 0；1,000 实体 / 24 小时在桶上限附近随哈希分布成败，成败都不能修正榜单。
- **边界**：只测了 Agentless 代表指标；节点、Agent 分片、生产版 Easysearch 3.0.0、PIT、并发与真实端到端须另行验证。
